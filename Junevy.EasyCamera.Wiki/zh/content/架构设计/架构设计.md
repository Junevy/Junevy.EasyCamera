## 本分类概述

本分类描述 Junevy.EasyCamera 的内部结构与设计约束：整体三层依赖、门面/注册表/观察者等设计模式的落点、帧从 SDK 回调到订阅者 handler 的完整生命周期与引用计数规则、以及配置对象与依赖注入的装配细节。该库的特殊之处在于它面对的是 C++ 厂商 SDK 与 5MB+ 非托管图像，因此架构约束不只是"分层好看"，而是由泄漏、use-after-free、静默丢帧等真实事故反推出来的：`AGENTS.md` 里的并发纪律（一切原生访问经 `operationGate`、生命周期用单一状态枚举、门面按 cameraKey 串行、流锁只保护订阅者注册表）都对应着 CHANGELOG 中记录的具体缺陷修复。

理解本分类的前提是先知道库在解决什么问题：它面向的是"第三方项目要接工业相机，但不想被品牌 SDK 绑死"的场景，稳定面只有 `ICameraService` 与 `ICameraSdkSystem` 两个类型（见 [[项目概述/项目介绍与目标]]）。新增厂商或修改生命周期代码前，务必先读本分类，尤其是"帧数据流与生命周期"一页——那里列出的每条规则都对应一类无法靠单元测试发现的内存问题（本仓库测试全绿，消费方仍可能因泄漏或悬空指针崩溃）。

| 架构事实 | 内容 |
|---|---|
| 分层 | 消费方 → Core 契约 → 实现层 → 厂商 SDK，单向不可逆 |
| 门面 | `CameraService`（业务）+ `EasyCameraHost`（资源作用域） |
| 注册表 | `CameraManager`（`cameraKey → ICamera`）、`StreamManager`（`cameraKey → ICameraStream`） |
| 聚合 | `AggregateCameraProvider`（多厂商）、`CompositeCameraSdkSystem`（多 SDK） |
| 帧分发 | 每订阅者一个有界 `Channel` + 独立 worker，观察者模式 |
| 帧所有权 | 每帧仅在采集回调中克隆一次，发布后引用计数浅共享，归零者物理释放 |
| 背压 | `DropOldest`（默认）/ `RejectNewest`，都不阻塞采集线程 |
| 并发门 | 厂商相机 `operationGate` + `ExecuteGuarded`/`TryExecuteGuarded`/`ExecuteDispose` |
| 生命周期状态 | 单一 `CameraState` 枚举（`Closed`/`Open`/`Grabbing`/`Closing`/`Disposed`） |
| 能力接口 | `ILinkStatusProbeProvider`/`IBufferConfigurable`/`INamedCameraInfo`/`IParameterSource` |
| 诊断出口 | `CameraResult`（`Code` 为厂商原生码）+ `ICamera.LastError` |
| 丢帧观测 | `FrameStreamStatistics`：`Published`/`Delivered`/`Dropped` |

三条最容易踩的架构性坑（详见对应子页面）：① 帧引用计数归零者才是释放者，不能固定为发布者；② 相机 `Close` 必须持 per-key 锁，否则与 `OpenCamera`/`StartGrab` 并发会 native use-after-free；③ 厂商独有能力一律加能力接口，加进基础接口就是破坏性变更。
