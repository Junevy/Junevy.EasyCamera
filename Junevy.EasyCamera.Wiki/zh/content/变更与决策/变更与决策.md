## 本分类概述

本分类记录"为什么今天的设计长这样"，分两页：

- [[变更与决策/设计决策记录]] 以 ADR 风格（背景 / 决策 / 理由 / 代价与边界）列出十条仍在生效的架构决策，每条都写明**放弃了什么**。核心是四条主线：帧所有权（每帧克隆一次 + 引用计数浅共享）、分发机制（Channels 有界队列 + 每订阅者 worker）、接口稳定性（能力接口隔离，默认值语义保守）、分发方式（厂商托管封装随包分发 + 双目标兼容存量宿主）。
- [[变更与决策/审查与修复记录]] 按时间线组织 2026-09-15 至 2026-10-06 的四轮全链路审查与修复，表格化给出日期/主题/关键问题/根因/修复/回归保障，并标注对应的回归测试文件，便于反向移除验证有效性。

这两页的方法论内核是同一条教训：**测试"全绿"不等于功能被验证**。2026-10-06 的证据是——仓库实有 98 个 `[TestMethod]`，只执行了 92 个，缺的 6 个恰是新增探测测试，而审查报告仍写"全量通过"。此后所有验收都要求核对 `[TestMethod]` 总数 == 执行数。

## 版本时间线

| 版本 | 日期 | 一句话 |
| --- | --- | --- |
| 1.0.0 | 2026-09 前后 | 初始发布面；随后做了一轮破坏性命名修正（v1.0.0 未对外发布的前提下直接改） |
| 1.0.1 | 2026-10-06 | 相机链路三态身份与非侵入可达性探测入库（**破坏性**：`ICameraProvider` 新增 `ProbeLinkStatus`） |
| 1.1.0 | 2026-10-06 | 审查修复三批 + 能力接口化 + 背压策略与丢帧可观测（**破坏性**，八条清单见 `SKILL.md`） |
| 1.1.1 | 2026-10-06 | 厂商 SDK 托管封装随包分发——修复消费方必崩（打包修复，必须清缓存升级） |
| 1.1.2 | 2026-10-08 | 审查修复批次 A：`IsConnected` 纯状态读取、`Close` 幂等、SDK 返回码检查、builder 去重、聚合 `Unknown` 回退、流滞留窗口（行为修正，无 API 变更；`Initialize` 对 SDK 错误码改为抛异常） |
| 1.2.0 | 2026-10-08 | 设备掉线检测与通知：海康 `Lost` 状态与设备异常回调（SDK 线程不进门）、`IConnectionMonitor`、门面 `CameraDisconnected` 事件、手动重连（同 key 再次 `OpenCamera`）；**新增公共 API**（`ICameraService` 新增事件），门面 `StopGrab` 对掉线相机返回成功；验收修正：`ICamera.Close` 对从未打开的相机幂等成功，关闭期间的掉线按释放处理 |

> [!tip]
> 1.1.0 与 1.1.1 同一天发布不是笔误：1.1.0 的验收刚过，消费方端到端验证就暴露出打包缺陷，1.1.1 是同一天的回补。两版都属于"破坏性/必须重装"的版本，消费方升级路径见 `SKILL.md` 末两节。
