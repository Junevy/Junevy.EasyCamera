# 代码审查报告（2026-10-05）

审查范围：`Junevy.EasyCamera.Core`、`Junevy.EasyCamera`（含 HikVision 适配、IRayple 适配）、`Junevy.EasyCamera.Tests`。
验证基线：`dotnet build`（Release）0 错误；`dotnet test` net48 / net8.0 各 63/63 通过。
与 `docs/稳定性审查报告-2026-09-15.md` 交叉核对：H1（worker 死亡帧滞留）、H2（帧 GC 兜底）、H3（AddRef/Dispose 竞态）、M1（WaitForCallbacks 超时）、M2（SDK 引用计数）、M3（StreamManager disposed）声明的修复大部分在位，唯 M3 实际缺失（见 一.1）。

## 一、隐藏 Bug（按严重度）

1. **StreamManager.GetOrCreateStream 缺少 disposed 防护（已声明修复但代码缺失，回归）**
   位置：`Common/StreamManager.cs:48-54`。CHANGELOG 2026-09-15 声称"释放后 GetOrCreateStream 抛 ObjectDisposedException"，实际只有 `GetStream`（71 行）有检查。Dispose 后调用会重建一个永远无人释放的 `CameraStream`。
2. **HikCameraSdkSystem.Initialize 并非幂等，SDK 永不 Finalize**
   位置：`Vendors/HikVision/HikCameraSdkSystem.cs:34`。接口与类注释均承诺"幂等（每实例持有一个引用）"，实际每次调用 `Interlocked.Increment`；同实例调用 N 次 Initialize 后 Dispose 只 Release 一次，全局引用计数永远 >0。
3. **HikCameraSdkSystem 的 Initialize/Release 交叉竞态**
   位置：`HikCameraSdkSystem.cs:54-67`。`Release` CAS 1→0 成功后、`SDKSystem.Finalize()` 执行前，并发的 `Initialize` 可 Increment 0→1 并调用 `SDKSystem.Initialize()`；Finalize 后执行将销毁在用 SDK。纯 CAS 无锁方案无法封死该窗口。
4. **CameraService.Close 语义混淆 + 门面依赖具体类**
   位置：`Common/CameraService.cs:202-209`。`TryRemove` 的 false 无法区分"key 不存在"与"释放失败"；`is CameraManager concrete` 具体类型嗅探破坏抽象；叠加 `CameraManager.LastError` 从不重置（`CameraManager.cs:129-133`），可能报出与本次无关的陈旧错误。
5. **重复订阅静默吞掉新订阅，语义自相矛盾**
   位置：`Common/CameraStream.cs:85-98`。同 key 再次 `Subscribe`：TryAdd 失败 → 新订阅者被销毁 → 方法无信号返回。调用方以为新 handler 生效。测试 `Subscribe_DuplicateKey_ShouldKeepSingleSubscriber` 的断言消息写"必须被替换"，实现却是"保留旧的"。
6. **CameraStream.Subscribe 中 worker 先于 candidate 赋值启动（脆弱模式）**
   位置：`CameraStream.cs:72-73`。`Task.Run` 闭包捕获尚未赋值的 `candidate` 局部变量，靠线程池调度时机保证 `self` 非 null，属靠巧合而非设计保证。
7. **CompositeCameraSdkSystem.Release/Initialize 缺少异常隔离**
   位置：`Common/CompositeCameraSdkSystem.cs:31-44`。`Dispose` 有 try/catch，Initialize/Release 没有：一个厂商抛异常将阻断其余厂商的初始化/释放。
8. **数值类 GetParam 静默截断**
   位置：`Vendors/HikVision/HikCamera.cs:597`（long→int 强转）、`Vendors/IRayple/IRaypleCamera.cs:393`。溢出静默回绕；叠加"失败返回 default(T)"，失败/溢出/取错类型对调用方完全不可见。
9. **次要项**
   - `CameraService.cameraOpenLocks` 只增不减（旧报告 M4 遗留，此前已接受）。
   - `SubscribeFrameStream` 契约是 bool，但流已释放时 `stream.Subscribe` 抛出的 `ObjectDisposedException` 直接外泄。
   - `StartGrab` 不幂等（重复调用报"already grabbing"失败），与 `StopGrab` 幂等风格不一致。
   - `HikFrameWrapper.Data`（`HikFrameWrapper.cs:57`）无 disposed 防护，且每次访问穿透 SDK `Image.PixelData`——若 SDK 每次访问重新拷贝，则每帧每次访问隐式分配 5MB+，违背"少分配"约定。
   - `HikCameraProvider.Enumerate`（`HikCameraProvider.cs:87-88`）枚举失败静默 `yield break`，无诊断。
   - IRayple 层（Obsolete，可接受，列入开发清单）：无同步（对比 HikCamera 的 operationGate）、Dispose 不等待在途回调、AddRef 释放后无防护、Connect 不校验 deviceInfo 为 null。

## 二、设计问题

1. `GetParam<T>` 用 default(T) 吞掉一切失败，绕开本库成熟的 `CameraResult` 错误通道；建议增加 `TryGetParam<T>` 重载（可扩展点，需确认）。
2. `ICameraStream.Publish` 接口注释（"发布方保留初始引用"）与实现（"初始引用转移给流并由流释放"）矛盾，所有权契约必须一致。
3. 服务层锁形同虚设：`StopGrab` 锁服务级 `locker`，`StartGrab`/`SetTrigger` 不锁，互斥无效（HikCamera 内部 operationGate 兜底，通用 ICamera 契约无此保证）。
4. `CameraResult.Code` 语义未定义：成功时有时是原生码、有时是魔数 1、有时是 0，无法编程判断。
5. 两个同名 `ServiceCollectionExtensions` 分居 `Junevy.EasyCamera.Extensions` 与 `Junevy.EasyCamera.Core.Extensions`（后者实际住在主程序集），接手者易混淆。
6. `ILineScanCamera` 为无成员无实现的空标记接口（保留为扩展点即可）；`HikCameraInfo.SetDefinedName` 只改本地副本字段，名字像会写入相机。

## 三、命名问题

1. `CameraStreamSuber` / 属性 `Suber`（实际是 Task）/ 参数 `subberKey`——"Suber" 为 Subscriber 错拼且全部是公开 API；服务层已用 `subKey`，两层不一致。
2. `CameraType` 名不副实：枚举值全是物理接口类型（GigE/USB/CameraLink/GenTL），`ICameraInfo` 属性叫 `InterfaceType`；成员 `ALL` 违反 .NET 枚举命名（应 `All`）。
3. `GetOnlineCameraSerialNumber(cameraKey)`：实际返回"已注册相机"的序列号，与"在线"无关。
4. `SetTrigger(triggerWay, isAcquisition)`：`triggerWay` 实为 TriggerSource 符号名；`isAcquisition` 实为 TriggerMode On/Off 开关，两个参数名都与职责错位。
5. 小项：`ICameraManager` 实为注册表（`TryRegister` false=已存在未注释）；锁字段四种风格混用（operationLock/operateLock/locker/operationGate）；`OpenCamera` 消息 "camerakey" 小写；csproj 包描述两处拼写错误（"A easy-to-use"、"Asynchronours"，NuGet 公开元数据）。

## 四、验证结论

构建 0 错误；测试 63/63 双目标通过；残留 25 警告（IRayple 遗留代码 17 条 CA1416——程序集声明 `windows` 而告警要求 6.1，以及测试代码 CS0067/SYSLIB0050）。帧生命周期主线与相机关闭主线设计扎实；优先处理 一.1～一.5。
