## CameraResult

`CameraResult` 是全库统一的返回值载体（类，不是结构体），只读属性为 `bool IsSuccess`、`int Code`、`string Message`。静态工厂：

| 工厂 | 语义 |
| --- | --- |
| `Result(bool result, int code, string message = "")` | 通用构造 |
| `Fail(int errorCode, string errMsg = "")` | 失败，`IsSuccess == false` |
| `Success(int code, string msg = "")` | 成功，`IsSuccess == true` |

另有公开构造函数 `CameraResult(bool isSuccess, int code)` 与 `CameraResult(bool isSuccess, int code, string msg)`。`Code` 约定：成功时是厂商原生成功码（通常 `0`），失败时是厂商原生错误码；没有厂商原生码时用 `-1`。

> [!warning] **调用方只准用 `IsSuccess` 判成败**。不要拿 `Code != 0` 之类的写法：不同厂商的成功码可能不同，门面层还会在厂商码之外引入自己的 `-1`/`-2`（例如 `OpenCamera` 的 "has been opened" 是 `-1`，内部异常翻成 `-2`）。需要具体原因时读 `Message`，需要厂商码时读 `Code`。

## CameraLinkStatus

五态，值只增不改：

| 成员 | 值 | 含义 |
| --- | --- | --- |
| `Unknown` | 0 | 未能判定 |
| `Connected` | 1 | 本进程已持有连接 |
| `Idle` | 2 | 在线、未被持有且可达，可打开 |
| `Occupied` | 3 | 在线但不可达，通常被其它客户端独占 |
| `Unreachable` | 4 | 重新枚举中不存在：掉线 / 未上电 |

> [!warning] 默认值必须是 `Unknown`。`default(CameraLinkStatus)` 会落到"未知"；若把任何"确定状态"排到 0，未初始化变量或漏赋值的代码路径就会谎报"已连接"。这个约束在 1.1.0 是硬约定，任何新增枚举都要遵守"未判定语义占 0"。判定顺序（不可交换）见 [[公共契约/ICameraService门面]]：先 `IsSerialConnected` → `Connected`，否则非侵入探测 → `Idle`/`Occupied`/`Unreachable`，探测不可进行 → `Unknown`。

## CameraInterfaceType

表示设备**物理接口类型**，与品牌无关（原名 `CameraType`，1.1.0 更名为 `CameraInterfaceType` 以消除"相机=接口"的歧义）。成员：`GigE`、`Usb`、`GenTL`、`CameraLink`、`All`、`Unknown`。其中 `All` 只用于**过滤参数**（`EnumerateCameras(CameraInterfaceType.All)` 是默认值），不是设备类型；该枚举无显式数值，按声明顺序默认从 0 开始，跨版本比较请用名称而非数值。

## CameraRemoveStatus

`ICameraManager.Remove(cameraKey)` 的返回值：

| 成员 | 值 | 含义 |
| --- | --- | --- |
| `Removed` | 0 | 已移除并释放成功 |
| `NotFound` | 1 | key 不存在（或管理器已释放） |
| `ReleaseFailed` | 2 | 已从注册表摘除，但 `Close`/`Dispose` 失败 |

`ReleaseFailed` 时诊断信息在 `ICameraManager.LastError`。门面 `Close` 把它映射为 `CameraResult.Fail(-1, "The camera has been removed from the registry and released, but the release reported errors: {LastError}")`（1.1.2 起）。

## ImagePixelFormat

库内统一的像素格式枚举，`Unknown = 0`，随后：单色 `Mono8`/`Mono10`/`Mono12`/`Mono14`/`Mono16`；Bayer `BayerRG8`/`BayerRG10`/`BayerRG12`/`BayerGB8`/`BayerBG8`；彩色 `RGB8`/`BGR8`；YUV `YUV422`/`YUV444`；打包格式 `Mono10Packed`/`BayerRG12Packed`。`HikFrameWrapper.ConvertFormat` 负责 `MvGvspPixelType` → `ImagePixelFormat` 映射，未识别的原生格式落到 `Unknown`（`switch` 的 `_` 分支）。

## FrameStreamStatistics

只读 `struct`，三个 `long` 成员 + 静态 `Empty`（等价 `default`）。`Dropped` 是三种情形的合计：无订阅者时发布、`TryWrite` 返回 `false`、通道 itemDropped 回调（背压淘汰）。读取入口为 `ICameraStream.Statistics` 与 `ICameraService.GetStreamStatistics(cameraKey)`；实现里用 `Interlocked.Read` 读取三个计数器（`long` 在 32 位平台上需要 64 位原子读），排错用法见 [[并发与资源/背压与丢帧统计]]。

| 成员 | 含义 |
| --- | --- |
| `Published` | 累计收到并尝试分发的帧数（每次 `Publish` 递增） |
| `Delivered` | 累计投递给订阅者 `handler` 的帧数（调用 handler 前递增） |
| `Dropped` | 累计未送达订阅者的帧数 |

> [!note] 计数口径：`Published` 按**帧**计，`Delivered`/`Dropped` 按**（帧 × 订阅者）**计，多订阅者时三者不满足 `Published = Delivered + Dropped`；详见 [[架构设计/帧数据流与生命周期]] 的"丢帧可观测性"。

## BackpressureMode

| 成员 | 值 | 语义 |
| --- | --- | --- |
| `DropOldest` | 0 | 默认。队列满时淘汰最旧帧，保留最新画面 |
| `RejectNewest` | 1 | 队列满时拒收新帧，已入队帧按序处理 |

> [!warning] **刻意不提供"丢新帧"模式**。实测 .NET `System.Threading.Channels` 的 `BoundedChannelFullMode.DropNewest` 与 `DropOldest` 行为完全一致（都淘汰最旧帧、保留最新帧），提供该选项只会名不副实。

`RejectNewest` 映射为 `BoundedChannelFullMode.Wait`，配合 `TryWrite`：队列满时直接返回 `false`，**不阻塞、不覆盖、不触发淘汰回调**，由发布方计入 `Dropped`。`DropOldest` 映射为 `BoundedChannelFullMode.DropOldest`，被淘汰的帧经通道的 `itemDropped` 回调释放引用。

## ICameraInfo

设备描述，只读：`SerialNumber`、`ModelName`、`UserDefinedName`、`Manufacturer`、`CameraVersion`、`CameraInterfaceType InterfaceType`。

- `SerialNumber` 是链路探测与 `IsSerialConnected` 的唯一匹配键；为空时 `ProbeCameraLinkStatus` 直接返回 `Unknown`。
- `UserDefinedName` 只能读。改名走 `INamedCameraInfo.SetDefinedName`，且只改本地副本，见 [[公共契约/能力接口与扩展点]]。

## ICameraManager 与 IStreamManager

`ICameraManager : IDisposable`（实现 `CameraManager`，内部 `ConcurrentDictionary<string, ICamera>` + `operationLock`）：

| 成员 | 说明 |
| --- | --- |
| `bool TryRegister(string cameraKey, ICamera camera)` | 返回 `false` 表示该 key 已注册 |
| `bool TryGet(string cameraKey, out ICamera camera)` | 未找到/已释放返回 `false` |
| `CameraRemoveStatus Remove(string cameraKey)` | 摘除并 `Close`+`Dispose`，即使 `Close` 失败也仍调 `Dispose` |
| `string LastError` | 最近一次释放失败的诊断信息；成功清理后清空为 `null` |
| `IEnumerable<KeyValuePair<string, ICamera>> Snapshot()` | 快照，已释放时返回空数组 |

`IStreamManager : IDisposable`（实现 `StreamManager`）：

| 成员 | 说明 |
| --- | --- |
| `ICameraStream GetOrCreateStream(string cameraKey)` | 释放后抛 `ObjectDisposedException`；构造 `CameraStream(cameraKey, options)` |
| `bool GetStream(string cameraKey, out ICameraStream stream)` | 不存在返回 `false` |
| `bool RemoveStream(string cameraKey)` | 移除并释放流；已释放时返回 `false` |

> [!tip] `Remove` 返回 `ReleaseFailed` 时 `LastError` 有值，成功路径下它被清空为 `null`。这是刻意设计：避免上一轮的陈旧错误被误当成本轮问题。多处排查时**先看返回值，再看 `LastError`**。

## ICameraSdkSystem 与 IStreamOptions

`ICameraSdkSystem : IDisposable`：`void Initialize()`（按实例幂等）、`void Release()`。多厂商场景用 `Junevy.EasyCamera/Common/CompositeCameraSdkSystem.cs` 组合；海康实现 `HikCameraSdkSystem` 用静态引用计数 + 全局锁管理 `SDKSystem.Initialize/Finalize`，详见 [[并发与资源/并发纪律]]。

`IStreamOptions`（实现 `StreamOptions`，构造默认值）：

| 成员 | 默认 | 说明 |
| --- | --- | --- |
| `int StreamCapacity` | 5 | 订阅 Channel 容量（帧数）；`SubscribeFrameStream` 的 `capacity <= 0` 时回落到它 |
| `int CameraBufferCapacity` | 0 | 相机内部采集缓冲数；`0` 表示用 SDK 默认值，仅 `IBufferConfigurable` 相机会应用 |
| `BackpressureMode BackpressureMode` | `DropOldest` | 背压策略 |
