## 目标框架与平台约束

| 项 | 取值 | 出处 |
|---|---|---|
| 目标框架 | `net48;net8.0`（两个类库与测试工程一致） | 三个 csproj 的 `<TargetFrameworks>` |
| 语言版本 | `LangVersion=13`（测试工程 `latest`） | 三个 csproj |
| 运行时位数 | `PlatformTarget=x64`（实现库与测试工程；Core 未设置） | `Junevy.EasyCamera.csproj`、`Junevy.EasyCamera.Tests.csproj` |
| 平台标注 | net8.0 下程序集级 `SupportedOSPlatform("windows")` | 两个类库各自的 `Properties/PlatformCompatibility.cs` |
| 确定性构建 | `Deterministic=true` | 两个类库 csproj |
| 自动打包 | `GeneratePackageOnBuild=true`，包 ID `Junevy.EasyCamera` / `Junevy.EasyCamera.Core` | 两个类库 csproj |

net48 面向存量 .NET Framework 宿主（该目标下使用 BCL 兼容包，见下表）；net8.0 面向新项目，BCL 已内置于共享框架，只需补 `System.Drawing.Common`。

> [!warning]
> `SupportedOSPlatform("windows")` 必须写在 `Properties/PlatformCompatibility.cs` 里（`#if NET8_0_OR_GREATER` 包裹），**不能**写在 csproj 的 `<AssemblyAttribute>` 项中：两个类库都设置了 `GenerateAssemblyInfo=false`（为使用手写的 `Properties/AssemblyInfo.cs`），该设置会连带跳过 `<AssemblyAttribute>` 项，导致平台标注**静默失效**——增量构建看不到任何异常，全量重建时才冒出 20+ 条 CA1416 告警。

## 厂商 SDK 引用与打包

厂商 SDK 的**托管封装**放在仓库根目录 `Libs/`：`MvCameraControl.Net.dll`（海康，本仓库 pin 的版本为 4.5.0.2，见 CHANGELOG 1.1.1 说明）与 `MVSDK_Net.dll`（华睿），由 `Junevy.EasyCamera.csproj` 以文件引用方式引入：

```xml
<Reference Include="MvCameraControl.Net">
  <HintPath>..\Libs\MvCameraControl.Net.dll</HintPath>
  <Private>true</Private>
</Reference>
```

同时用无条件 `Pack` 项打进 NuGet 包：

```xml
<None Include="..\Libs\MvCameraControl.Net.dll" Pack="true" PackagePath="lib/net48;lib/net8.0" Visible="false" />
<None Include="..\Libs\MVSDK_Net.dll" Pack="true" PackagePath="lib/net48;lib/net8.0" Visible="false" />
```

> [!danger]
> 这段打包写法有两条硬约束（都是踩过的坑，改动前必须先读 `docs/代码审查报告-2026-10-06.md`）：① `PackagePath` 必须逐个 TFM 写全（`lib/net48;lib/net8.0`），写成与 TFM 无关的 `lib/` 时，NuGet 会因为包内已存在 `lib/<tfm>/` 目录而**整体忽略**根目录文件；② **禁止**按 `$(TargetFramework)` 分条件 ItemGroup——多目标项目打包走外层构建，此时 `$(TargetFramework)` 为空，条件恒不成立，DLL 会被静默漏掉。新增品牌照此追加。

背景：`<Reference HintPath>` + `Private=true` 只让本仓库自己的输出目录拿到 DLL，`dotnet pack` 既不打包文件引用也不产生依赖声明，消费方必然 `FileNotFoundException`。因此 1.1.1 明确"托管封装随包分发"，而厂商**原生**驱动（`MvCameraControl.dll`）仍不在包内——两件事务必分开表述，消费方视角的完整要求见 [[项目概述/运行与安装前置条件]]。打包规则由 `Tests/Packaging/PackageContentTests.cs` 守卫：定位仓库根、取最新 nupkg，断言两个 TFM 下均含两份厂商 DLL；无产物时断言为 Inconclusive，不产生假失败。

## 工具链与代码规范固定

| 文件 | 作用 |
|---|---|
| `global.json` | 固定 .NET SDK `9.0.316`，`rollForward=latestFeature`，保证构建/测试可复现 |
| `Directory.Packages.props` | 中央包管理（`ManagePackageVersionsCentrally=true`），集中声明全部**第三方**包版本（本库版本不在此） |
| `.editorconfig` | 仓库根 `root = true`；`[*.cs]` 缩进 4 空格、`end_of_line = crlf`、命名空间匹配文件夹、括号/成员限定等 .NET 约定 |

程序集特性（`AssemblyTitle`、`AssemblyVersion`/`AssemblyFileVersion` = `1.1.1.0`、`InternalsVisibleTo("Junevy.EasyCamera.Tests")`）写在手写的 `Properties/AssemblyInfo.cs` 中，因此 csproj 必须 `GenerateAssemblyInfo=false`。`InternalsVisibleTo` 是测试 seam 的通道：`HikCameraSdkSystem.SdkInitializeAction`/`SdkFinalizeAction` 两个 internal 静态委托供无硬件单测替换真实 SDK。

## 测试技术栈

- MSTest 3.6.4 + `Microsoft.NET.Test.Sdk` 17.14.1，`OutputType=Library`，`IsTestProject=true`。
- `PlatformTarget=x64`（厂商 SDK 为 AMD64 专用），`CopyLocalLockFileAssemblies=true`（确保 NuGet 运行时资产随测试输出落盘）。
- `EnableDefaultCompileItems=false` + 显式 `<Compile>` 清单：**新增测试文件必须手工加入 csproj**，否则不会被编译、更不会执行（2026-10-06 曾因此让 6 个探测测试"绿色地缺席"）。验收时应核对"仓库内 `[TestMethod]` 总数 == 执行数"（当前两者均为 130）。
- `NoWarn`：NU1605、SYSLIB0011、SYSLIB0050、CS0067（构造 SDK 的 `FrameGrabbedEventArgs` 只能走 `FormatterServices.GetUninitializedObject`；厂商 SDK 接口要求桩类型保留事件成员）。
- 消费方只需正常 `PackageReference`；本文只讲仓库侧的技术栈，消费方的安装与排错见 [[项目概述/运行与安装前置条件]]。
