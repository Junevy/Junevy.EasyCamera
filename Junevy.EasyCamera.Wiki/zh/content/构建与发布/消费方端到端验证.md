## 验证目的

包内容守卫（[[构建与发布/包内容守卫]]）能证明"文件在包里"，但不能证明"消费方真的能跑起来"。本流程用一个**只引用本地 nupkg、零手工拷贝 DLL** 的最小项目端到端确认，是 1.1.1 的验收方式。

验证覆盖 `net8.0` 与 `net48` 两个宿主，因为打包路径、TFM 资产与运行时解析规则都不同。

## 准备：清缓存与产出 nupkg

```powershell
# 1) 清掉旧版本缓存（同版本重发不生效，且缓存会骗人）
Remove-Item -Recurse -Force "$env:USERPROFILE\.nuget\packages\junevy.easycamera*" -ErrorAction SilentlyContinue

# 2) Release 全量重建（GeneratePackageOnBuild=true 会顺带打包）
cd D:\Desktop\doc\Github_Repository\Junevy.EasyCamera
dotnet build .\Junevy.EasyCamera.sln -c Release -v:minimal --no-incremental

# 3) 确认产物
Get-ChildItem .\Junevy.EasyCamera\bin\Release -Filter *.nupkg
```

> [!warning]
> NuGet 缓存会骗人：本次验证过程中就曾因全局缓存命中旧的 1.1.0 包而误判"修法无效"，白查一轮。验证前务必清 `junevy.easycamera*` 缓存，或对消费方项目加 `dotnet restore --force`。若本机把缓存放在自定义 `RestorePackagesPath`，要删的是**那个目录**下的条目。

## 建临时消费方项目

`net8.0` 与 `net48` 各建一份，指向同一个临时 feed：

```powershell
$feed = "D:\AppTemp\opencode\easycamera-feed"
$pkgs = "D:\AppTemp\opencode\easycamera-cache"
New-Item -ItemType Directory -Force -Path $feed, $pkgs | Out-Null

# 主包的 nuspec 依赖同版本的 Junevy.EasyCamera.Core，两个 nupkg 都要进 feed，否则还原找不到 Core
Copy-Item .\Junevy.EasyCamera\bin\Release\Junevy.EasyCamera.1.1.1.nupkg $feed
Copy-Item .\Junevy.EasyCamera.Core\bin\Release\Junevy.EasyCamera.Core.1.1.1.nupkg $feed

# 临时 feed 配置：只从本地目录取本包，其余走 nuget.org
@"
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="local-easycamera" value="$feed" />
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
  </packageSources>
</configuration>
"@ | Set-Content -Encoding UTF8 "$feed\nuget.config"
```

项目骨架（`<TFM>` 替换为 `net8.0` 或 `net48`）：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <PlatformTarget>x64</PlatformTarget>
    <RestorePackagesPath>D:\AppTemp\opencode\easycamera-cache</RestorePackagesPath>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Junevy.EasyCamera" Version="1.1.1" />
    <PackageReference Include="Microsoft.Extensions.DependencyInjection" Version="8.0.0" />
  </ItemGroup>
</Project>
```

还原与运行：

```powershell
cd D:\AppTemp\opencode\consumer-net8
dotnet restore --force
dotnet run -c Release
```

## 消费方代码只有三件事

```csharp
using Junevy.EasyCamera.Extensions;
using Junevy.EasyCamera.Core.Abstractions;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddEasyCamera(o => o.EnableHikVision = true);
using var sp = services.BuildServiceProvider();

var sdk = sp.GetRequiredService<ICameraSdkSystem>();
sdk.Initialize();
Console.WriteLine("Initialize OK");

var infos = sp.GetRequiredService<ICameraProvider>().Enumerate().ToList();
Console.WriteLine($"EnumerateCameras OK, count={infos.Count}");
```

故意只覆盖"注册 → SDK 初始化 → 枚举"三步：这三点足以暴露包内缺托管封装（`Initialize` 的类型初始化异常）与原生运行时缺失（枚举不到设备）两类问题，不必引入真实相机。

## 期望结果

无相机接入的机器上：

```
Initialize OK
EnumerateCameras OK, count=0
```

`count=0` 是**正常**的，前提是本机装有 MVS 运行时且 `...\Common Files\MVS\Runtime\Win64_x64` 在 PATH（安装程序通常自动配置）。

同时应能在构建输出目录看到 `MvCameraControl.Net.dll` 与 `MVSDK_Net.dll`——它们由 NuGet 资产复制而来，**不是**你手工拷的：

```powershell
Get-ChildItem .\bin\Release\net8.0 -Filter *.dll | Select-Object Name
```

## 失败对照表

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| `FileNotFoundException: Could not load file or assembly 'MvCameraControl.Net, Version=4.5.0.2'` | 包内缺厂商托管封装：拿到的是 ≤1.1.0 的包，或缓存未清 | 升到 1.1.1+ 并清 `junevy.easycamera*` 缓存；检查 `csproj` 的 `Pack` 项 |
| `AggregateException: The type initializer for 'HikCameraSdkSystem' threw an exception` | 同上，`Initialize` 路径上的表现 | 同上 |
| `DllNotFoundException`，或托管封装已在却枚举不到设备 | 厂商**原生**运行时未安装或不在 PATH | 安装 MVS 运行时，确认 `...\Common Files\MVS\Runtime\Win64_x64` 在 PATH |
| `BadImageFormatException` | 宿主非 x64 | 消费方工程加 `<PlatformTarget>x64</PlatformTarget>` |
| 手工拷了 DLL 到 exe 旁边仍然崩 | 对 .NET Core 无效 | 见下方 danger，必须走 NuGet 分发 |
| `dotnet restore` 报 `NU1101`（找不到 `Junevy.EasyCamera.Core`）或还原到非预期的 Core 版本 | 临时 feed 里只放了主包，没放同版本的 Core nupkg | 把 `Junevy.EasyCamera.Core.<ver>.nupkg` 也复制进 feed，并清缓存 |

> [!danger]
> **手工把厂商 DLL 拷到 exe 旁边对 .NET Core 无效。** .NET Core 的程序集解析走 `deps.json` 的 TPA（trusted platform assemblies）列表，默认加载器**不探测 exe 目录**。直觉性的第一反应（拷 DLL）是错的路，会把排查方向完全带偏。判断依据是"输出目录里有没有这两份 DLL（由 NuGet 资产复制而来）"，而不是"你有没有手动复制"。

> [!tip]
> 托管封装缺失与原生运行时缺失的报错形态相似但成因不同，排错时**先区分这两层**：`FileNotFoundException` 指向包内缺文件，`DllNotFoundException` 指向环境缺驱动。包修得了第一层，修不了第二层——后者是消费方的前置条件。详见 [[项目概述/运行与安装前置条件]]。

## 实测结论

1.1.1（2026-10-06）：`net8.0` 与 `net48` 消费方均通过——`Initialize OK`、`EnumerateCameras OK`，**零手工拷贝 DLL**。

同批验收：`dotnet build`（sln，Release，`--no-incremental`）0 错误 0 警告；`dotnet test` net48 124/124、net8.0 124/124。
