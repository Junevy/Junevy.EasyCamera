## 模式总表

| 模式 | 本仓库落点 | 为什么这么选 |
|---|---|---|
| 抽象工厂 | `ICameraProvider.Create(info, stream)` | 门面只知道"能创建一个 `ICamera`"，不知道厂商类型；换硬件不改门面 |
| 适配器 | `HikCamera` 包装海康 `IDevice`/`IStreamGrabber`/`IFrameOut` | 把 `int` 错误码、`MvException`、AMD64 原生句柄统一成 `CameraResult` + `IFrame` |
| 组合 | `AggregateCameraProvider`、`CompositeCameraSdkSystem` | 厂商数量可变；组合可复用既有实现，且能在枚举/初始化时给出聚合语义 |
| 门面 | `CameraService`、`EasyCameraHost` | 收敛 per-key 串行、错误翻译、资源作用域，让消费方只见两个入口 |
| 注册表 | `CameraManager`、`StreamManager` | 以 `cameraKey` 为键管理实例，支持重开、快照扫描、按序列号查找 |
| 策略 | `BackpressureMode`（`DropOldest`/`RejectNewest`） | 丢帧语义因场景而异（预览 vs 线阵测量），必须运行时可换 |
| 模板方法 + 守卫 | `HikCamera.ExecuteGuarded`/`TryExecuteGuarded`/`ExecuteDispose` | 互斥、异常翻译、诊断三件事只写一次，杜绝"某条路径漏加锁" |
| 接口隔离（能力接口） | `ILinkStatusProbeProvider`、`IBufferConfigurable`、`INamedCameraInfo`、`IParameterSource` | 厂商独有能力不进基础接口，避免每加一个能力就破坏所有实现者 |
| 观察者 + Channel | `CameraStream` + 每订阅者 `CameraStreamSubscriber` | 采集线程绝不阻塞；有界队列 + 背压把过载转化为可统计的丢帧 |
| 引用计数 | `HikFrameWrapper`（`refCount` + `refLock`） | 一帧要同时喂给多个订阅者与采集回调，浅共享同一克隆时必须有明确释放责任 |

## 抽象工厂与适配器

`ICameraProvider` 只保留所有厂商都必须支持的四个成员：`Supports(ICameraInfo)`、`Create(ICameraInfo, ICameraStream)`、`Enumerate()`、`Enumerate(CameraInterfaceType)`。门面 `CameraService.OpenCamera` 调 `provider.Create(info, stream)` 拿到 `ICamera`，此后一切操作经接口——这正是"通过接口无缝更换相机硬件"的机制基础。

`HikCamera` 是典型适配器：把海康 SDK 的 `MvError` 整数码（`MvError.MV_OK` 比较）、`MvException`（带 `ErrorCode`）、`IStreamGrabber.StartGrabbing/StopGrabbing`、`IParameters.SetIntValue/SetEnumValueByString`、`IFrameOut.Clone/FreeImageBuffer` 全部翻译为 `CameraResult`（`Code` 保留厂商原生码供诊断，`Message` 可读）与 `IFrame`。`ICamera.LastError` 是厂商诊断的**唯一**出口，门面必须把它透传到 `CameraResult.Message`。

## 组合与门面

- `AggregateCameraProvider` 实现 `ICameraProvider` + `ILinkStatusProbeProvider`：`Enumerate` 用 `SelectMany` 合并所有厂商设备；`Create` 用 `FirstOrDefault(v => v.Supports(info))` 分发，无厂商支持则抛 `ArgumentException`；`ProbeLinkStatus` 以能力探测方式分发，全都不支持时返回 `CameraLinkStatus.Unknown`；同时以显式接口实现提供 internal 的 `IProbeAvailability.CanProbe`，让 `CameraService` 区分"无人能探测"（→ 回退侵入式探测）与"厂商如实报告 `Unknown`"（→ 终态），见 [[公共契约/能力接口与扩展点]]。
- `CompositeCameraSdkSystem` 组合多个 `ICameraSdkSystem`：`Initialize`/`Release` 逐个调用，单个失败不中断其余，全部处理完后抛 `AggregateException`；`Dispose` 吞异常，避免中断其余 SDK 的清理。
- `CameraService` 是主门面：`ConcurrentDictionary<string, object> cameraKeyLocks` + `GetKeyLock(cameraKey)` 让 `OpenCamera`/`Close`/`StartGrab`/`StopGrab`/`SetTrigger` 按 key 串行；`OpenCamera` 内处理"已注册/竞争胜出/Connect 失败清理"三条路径（失败候选不得留在缓存中阻塞重试）。
- `EasyCameraHost` 是资源作用域门面：持有 `Sdk`/`Service`/`Options`，`Dispose` 幂等（`Interlocked.Exchange`）并按"相机 → 帧流 → SDK"释放。

## 注册表

`CameraManager`（`cameraKey → ICamera`）与 `StreamManager`（`cameraKey → ICameraStream`）都是注册表模式：

| 要点 | 实现 |
|---|---|
| 原子注册 | `cameras.TryAdd`；`false` 表示 key 已注册，调用方改用 `TryGet` |
| 移除语义 | `Remove` 返回 `CameraRemoveStatus`：`Removed`/`NotFound`/`ReleaseFailed`，避免"相机不存在"与"释放失败"混为一谈 |
| 锁纪律 | 字典锁只保护注册表状态；原生 `Close`/`Dispose` 在锁外执行 |
| 诊断 | `LastError` 提升到 `ICameraManager`，成功清理后清空，消除陈旧错误 |
| 非键维度扫描 | `Snapshot()` 返回只读快照，供 `IsSerialConnected` 按序列号匹配 |
| disposed 防护 | `StreamManager` 释放后 `GetOrCreateStream` 抛 `ObjectDisposedException`，竞态新建的流就地释放 |

## 策略：背压

`BackpressureMode` 只有两个值，`CameraStream.ToFullMode` 一次性映射为 `BoundedChannelFullMode`：

| 策略 | 值 | 映射 | 行为 | 适用 |
|---|---|---|---|---|
| `DropOldest` | 0（默认） | `BoundedChannelFullMode.DropOldest` | 淘汰最旧帧、保留最新画面 | 实时预览、状态判定 |
| `RejectNewest` | 1 | `BoundedChannelFullMode.Wait` + 发布方用 `TryWrite` | 队列满时 `TryWrite` 返回 false，不覆盖已入队帧；由发布方计入丢帧 | 线阵测量、缺陷计数（不能丢帧也不能乱序） |

> [!tip]
> 刻意**不提供"丢新帧"**选项：实测 `System.Threading.Channels` 的 `BoundedChannelFullMode.DropNewest` 与 `DropOldest` 行为完全一致（都淘汰最旧帧），提供该选项只会名不副实。两种策略都不阻塞采集线程——宁可丢帧，绝不拖慢采集。

## 模板方法与守卫

`HikCamera` 用三个守卫把"互斥 + 异常翻译 + 诊断"收敛到一处：

| 守卫 | 签名要点 | 用途 |
|---|---|---|
| `ExecuteGuarded` | `CameraResult ExecuteGuarded(Func<CameraResult> action)` | `Connect`/`Close`/`StartGrab`/`StopGrab`/`SetParam`×4/`SetEnumParam`/`ExecuteCommand`/`IBufferConfigurable.SetBufferCount` |
| `TryExecuteGuarded<T>` | 以 `Func<(bool Ok, T Value)>` 表达结果，不允许在 lambda 中用外层 `out` 参数 | `TryGetParam<T>`、`TryGetEnumParam` |
| `ExecuteDispose` | `void ExecuteDispose(Action)`，吞异常并记 `LastError` | `Dispose` |

三者都 `operationGate.Wait()` / `finally Release()`；`ExecuteGuarded` 单独捕获 `MvException` 取 `ErrorCode` 作为 `CameraResult.Code`。这直接对应 CHANGELOG 记录的缺陷："海康参数/命令路径完全在互斥之外"——此前 `SetParam`/`TryGetParam` 等既不加锁也不经 `operationGate`，与 `Dispose` 并发时会抛 `NullReferenceException` 直接穿透到调用方，破坏"失败一律走 `CameraResult`"契约。

生命周期用单一 `CameraState` 枚举（`Closed`/`Open`/`Grabbing`/`Closing`/`Disposed`）取代原先五个布尔标志位（`isOpen`/`isGrabbing`/`closing`/`callbacksEnabled`/`disposed`），从结构上排除非法组合；帧回调的发布判定退化为一次状态比较。

## 接口隔离与能力接口

| 能力接口 | 表达的能力 | 当前实现者 |
|---|---|---|
| `ILinkStatusProbeProvider` | 非侵入式可达性探测（`ProbeLinkStatus`） | `HikCameraProvider`、`AggregateCameraProvider` |
| `IBufferConfigurable` | 采集端缓冲配置（`SetBufferCount`） | `HikCamera`（显式实现）；`HikCameraProvider.Create` 按 `CameraBufferCapacity` 能力探测后调用 |
| `INamedCameraInfo` | 本地改名（`SetDefinedName`，长度 ≤64，仅改本地副本不下发设备） | `HikCameraInfo`（显式实现） |
| `IParameterSource` | 6 个取参原语（int/long/float/double/bool/string） | `HikCamera`、`IRaypleCamera`（显式实现） |

取参的泛型分发统一由 `ParameterReader.TryRead<T>(IParameterSource, paramName, out value)` 完成，厂商不再各写一遍 `typeof` 链；含 long→int 受检转换（越界按"取值失败"返回 `default`，禁止静默回绕）。

## 观察者与 Channel

`CameraStream` 是观察者模式的通道化实现：每个订阅者一个 `Channel<IFrame>`（`SingleReader = true`、`SingleWriter = false`、`AllowSynchronousContinuations = false`）与一个 worker 任务；`Subscribe` 建立通道并启动 worker，`Publish` 遍历订阅者快照 `AddRef + TryWrite`。

要点：

- 同 `subscriberKey` 重复订阅是**原子替换**（先构造候选订阅者再进锁竞争，胜出后在锁外 `Dispose` 旧订阅者）。
- 锁纪律：`operationLock` 只保护订阅者注册表；`AddRef`/`TryWrite`/背压淘汰/5MB 帧释放/用户 `whenException` 回调全部锁外执行。
- 丢帧统计 `Published`/`Delivered`/`Dropped` 由 `Interlocked` 累计，经 `ICameraStream.Statistics` 与 `ICameraService.GetStreamStatistics(cameraKey)` 暴露。

## 引用计数

`HikFrameWrapper` 用 `refCount`（初始 1，由发布方持有）+ `refLock` 短临界区：每入队一个订阅者 +1，**引用归零时由最后一个释放者物理释放**非托管缓冲，且仅释放一次（`Interlocked.Exchange(ref disposed, 1)`）。

- 不能把释放责任固定为发布者：其余浅引用会悬空。
- `Dispose` 幂等：重复释放不会把计数压到负数。
- 终结器兜底：订阅方忘记 `Dispose` 时由 GC 释放克隆帧的非托管缓冲；正常释放后 `GC.SuppressFinalize`。
- 宽高/步长/像素格式/大小在**构造时一次性快照**；`Data`（懒缓存托管副本）、`PixelDataPtr`、`GetBitmap` 统一在 `refLock` 内访问原生内存，与物理释放互斥，消除"先判已释放再读原生内存"的 check-then-use 竞态。

## 设计纪律：新增能力只加接口

> [!warning]
> **厂商独有能力一律用独立能力接口表达，不得再加进 `ICameraProvider`/`ICamera` 等基础接口。** 历史上把 `ProbeLinkStatus` 塞进 `ICameraProvider` 直接造成 1.0.0 → 1.1.0 的破坏性变更：基础接口每加一个成员，所有外部实现者（含第三方品牌）都被迫修改。1.1.0 的重构把这三项能力移出基础接口，改由调用方按能力探测 + 回退策略处理，新增能力从此不再破坏既有实现者。

同理，能力显式实现（`HikCamera.SetBufferCount`、`HikCameraInfo.SetDefinedName`、`HikCamera` 的 `IParameterSource` 原语）让它们不出现在具体类的公开面上——公开面是契约，能力是可选扩展点。

帧相关的所有权语义详见 [[架构设计/帧数据流与生命周期]]。
