# 2026-09-14

## Core/Common 架构重构（Junevy.EasyCamera 解决方案）

- 将 `Junevy.EasyCamera.Core/Common` 下 8 个实现类（AggregateCameraProvider、CameraManager、CameraService、CameraStream、CameraStreamSuber、CompositeCameraSdkSystem、StreamManager、StreamOptions）迁移至主项目 `Junevy.EasyCamera/Common`，命名空间改为 `Junevy.EasyCamera.Common`。
- 在 Core 新增 4 个接口（保留于 `Junevy.EasyCamera.Core.Common` 命名空间）：`ICameraManager`、`ICameraService`、`IStreamManager`、`IStreamOptions`；实现类分别实现之。CameraStreamSuber 未抽接口（内部协作类，暴露 Channel/Cts 等框架类型，抽接口会迫使 Core 保留 Channels 依赖）。
- Core 的 `AddEasyCameraCore`（DI 注册）随实现迁到主项目文件 Extensions/ServiceCollectionExtensions.cs，**保留原命名空间 `Junevy.EasyCamera.Core.Extensions` 与类名 `ServiceCollectionExtensions`** 以维持对外契约；DI 同时注册具体类型与接口（接口转发到同一单例，测试已断言 AreSame）。
- Core 瘦身：csproj 仅保留 System/System.Core/System.Drawing 引用，packages.config 清空；主项目补充 System.Threading.Channels 引用（CameraStream 需要）。
- 验证：本机无 VS MSBuild、无 net48 目标包。用 `dotnet build` + `FrameworkPathOverride` 指向 NuGet 包 `Microsoft.NETFramework.ReferenceAssemblies.net48` 1.0.3 解压出的 v4.8 引用程序集完成三项目编译（0 警告 0 错误）；`nuget restore`（6.12.4，取自 NuGet.CommandLine nupkg）恢复测试包；`dotnet vstest --TestAdapterPath` 跑通 46/46 测试。测试 csproj 的临时显式引用已还原，仓库保持原 PackageReference 配置。

### 本机构建坑（重要）
- 旧式 csproj（packages.config）用 `dotnet build` 会报 NuGet.targets "path1" 错误，需 `--no-restore` + 手动 nuget.exe restore；PackageReference 项目 restore 后 dotnet build 仍不解析包引用，需临时加显式 HintPath 引用才能编译/跑测试。
- `FrameworkPathOverride` 可通过环境变量传入。
- 沙箱曾出现一次 Core 整目录意外丢失（原因不明，疑似外部进程），已用 git restore + 重写文件恢复；操作目录时注意逐步验证。
