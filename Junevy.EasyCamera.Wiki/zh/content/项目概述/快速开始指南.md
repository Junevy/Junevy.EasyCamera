## 两种入口怎么选

| 场景 | 入口 | 说明 |
|---|---|---|
| Host / `IServiceProvider` / Microsoft.Extensions.DependencyInjection | `services.AddEasyCamera(...)` | 核心服务全部单例注册，可安全注入 `IHostedService` |
| Prism 等自带容器的框架 | `EasyCamera.Create(b => ...)` → `EasyCameraHost` | 把 `host.Sdk`/`host.Service` 以**单例实例**注册进宿主容器 |

两条路径的运行语义完全一致：`ICameraSdkSystem.Initialize()` 必须显式调用，`ICameraService` 的用法（枚举/开关/订阅/参数）完全相同。

## 依赖注入入口

注册（`Junevy.EasyCamera.Extensions` 命名空间）：

```csharp
services.AddEasyCamera(
    options => options.EnableHikVision = true,
    stream =>
    {
        stream.StreamCapacity = 5;                            // 每订阅者的有界帧缓存（帧数）
        stream.BackpressureMode = BackpressureMode.DropOldest; // 队列满时丢最旧（默认）
        // stream.BackpressureMode = BackpressureMode.RejectNewest; // 拒收新帧、按序处理已入队帧
        stream.CameraBufferCapacity = 10;                     // 采集端缓冲（仅部分厂商支持）
    });
```

- `AddEasyCamera` 可重复调用，不重复注册（内部一律 `TryAddSingleton` / `TryAddEnumerable`）。
- `AddHikVisionCamera()` 是仅启用海康的快捷方法；`AddIRaypleCamera()` 存在但调用即抛 `NotImplementedException`。
- 核心服务（`ICameraService`、`ICameraManager`、`IStreamManager`、`ICameraProvider`、`StreamOptions`、`HikCameraSdkSystem`、`ICameraSdkSystem`）均为单例。

生命周期（建议放在 `IHostedService` 中）：

```csharp
var sdk = provider.GetRequiredService<ICameraSdkSystem>();
sdk.Initialize();                     // 进程级一次；按实例幂等，引用归零才真正 Finalize
try
{
    var cameraService = provider.GetRequiredService<ICameraService>();
    // …… 见「典型使用序列」……
}
finally
{
    sdk.Dispose();                     // 释放本实例持有的全局引用
}
```

> [!warning]
> 只注入 `ICameraService` 而从不调用 `sdk.Initialize()` 是最常见的"枚举不到设备"原因：SDK 未初始化时厂商枚举无法工作。

## 非 DI 入口与 Prism 接入

```csharp
using Junevy.EasyCamera;

using var host = EasyCamera.Create(b => b.EnableHikVision()
                                         .WithStreamOptions(o => o.StreamCapacity = 5));
host.Sdk.Initialize();
// host.Service 的用法与 DI 路径完全一致
host.Dispose();   // 幂等；释放顺序：相机 → 帧流 → SDK
```

`EasyCameraHost` 持有 `Sdk`、`Service`、`Options`（Builder 内部那份 `StreamOptions` 实例**本身**，与 `StreamManager`/`CameraService` 共享，不是只读快照——构建后再改它会影响此后新建的订阅与相机，已建立的订阅不受影响），`Dispose()` 幂等并按"相机 → 帧流 → SDK"释放，保证 SDK `Finalize` 不早于任何相机释放。`Build()` 不做原生调用，初始化必须显式触发。

Prism 接入要点：

```csharp
protected override void RegisterTypes(IContainerRegistry containerRegistry)
{
    this.cameraHost = EasyCamera.Create(b => b.EnableHikVision());
    this.cameraHost.Sdk.Initialize();

    containerRegistry.RegisterInstance<ICameraSdkSystem>(this.cameraHost.Sdk);
    containerRegistry.RegisterInstance<ICameraService>(this.cameraHost.Service);
}
```

> [!danger]
> 必须 `RegisterInstance`（单例），**切勿注册为瞬态**：`CameraService` 背后共享 `CameraManager` 与 `StreamManager` 两张注册表，瞬态会出现两套互不相通的相机缓存与订阅流。若 Prism 底层本就是 Microsoft.Extensions.DependencyInjection（官方适配包），直接 `services.AddEasyCamera(...)` 即可。

## 典型使用序列

`cameraKey` 是贯穿相机与帧流的唯一句柄：相机以它注册，其帧数据流也以它创建，因此订阅/退订必须使用相同的 `cameraKey`。

```csharp
var info = cameraService.EnumerateCameras().First();          // 1. 枚举（失败为空序列 + Trace 警告）
var opened = cameraService.OpenCamera(info, cameraKey: "cam-1"); // 2. 打开（检查 opened.IsSuccess）

// 3. 订阅；capacity <= 0 时使用 StreamOptions.StreamCapacity
cameraService.SubscribeFrameStream("cam-1", "my-subscriber",
    (cameraKey, frame) =>
    {
        using (frame)                       // 帧必须 Dispose：引用计数归零即释放非托管缓冲
        {
            var data = frame.Data;          // 托管副本（安全）
            // 需要跨异步保帧时先 frame.AddRef()，用完对应 Dispose()
        }
        return Task.CompletedTask;
    },
    whenException: ex => { /* 不提供时 handler 异常将终止该订阅并自动摘除 */ });

cameraService.StartGrab("cam-1");                            // 4. 开始取流（幂等）
cameraService.SetParam("cam-1", "ExposureTime", 5000f);     // 5. 参数
if (cameraService.TryGetParam<int>("cam-1", "Width", out var width)) { /* 取参推荐 Try 版 */ }
cameraService.StopGrab("cam-1");                             // 停止取流（幂等）

cameraService.SetTrigger("cam-1", "Line1", enableTrigger: true); // 6. 设置触发：内部会停流
cameraService.StartGrab("cam-1");                               // 设置后必须重新 StartGrab

var stats = cameraService.GetStreamStatistics("cam-1");       // 7. 排查丢帧：Published/Delivered/Dropped
cameraService.Close("cam-1");                                 // 8. 关闭相机（帧流保留）
```

关停顺序建议：停流 → 退订（`UnsubscribeFrameStream`）→ `Close(cameraKey)` → `sdk.Dispose()`。

关键语义：

| 调用 | 语义 |
|---|---|
| `OpenCamera` | **非幂等**：同 key 已连接时返回失败（"The camera has been opened"），需先 `Close` 或复用 |
| `StartGrab` / `StopGrab` | 均幂等；`StopGrab` 返回厂商失败原因与 `LastError` |
| `SetTrigger` | 内部先 `StopGrab`；调用方必须随后重新 `StartGrab`，否则不出帧 |
| `TryGetParam<T>` | 可区分"值恰为 default"与"取参失败"；支持 int/long/float/double/bool/string |
| `Close` | 释放相机但**不删帧流**：重开同名 key 后既有订阅自动继续生效 |
| 同 `subscriberKey` 重复订阅 | 原子替换旧订阅者 |
| `ProbeCameraLinkStatus` | 五态链路探测，**应在后台线程调用** |

帧生命周期细则见 [[架构设计/帧数据流与生命周期]]。

## 注册与构建的异常行为

| 触发条件 | 异常 | 位置 |
|---|---|---|
| `options.EnableIRayple = true` | `NotImplementedException`（"IRayple camera support is not yet implemented."） | `ServiceCollectionExtensions.RegisterIRayple` / `EasyCameraBuilder.EnableIRayple` |
| `options.EnableBasler = true` | `NotImplementedException`（"Basler camera support is not yet implemented."） | `RegisterBasler` / `EnableBasler` |
| Builder 未启用任何厂商即 `Build()` | `InvalidOperationException`（"At least one camera vendor must be enabled before Build()."） | `EasyCameraBuilder.Build` |
| `services == null` | `ArgumentNullException` | `AddEasyCamera` / `AddEasyCameraCore` |

> [!tip]
> `StreamManager` 必须拿到**同一份** `StreamOptions` 实例，否则 `StreamCapacity` 与 `BackpressureMode` 不生效（Builder 路径已保证：`new StreamManager(this.streamOptions)` 与 `CameraService` 共用同一对象）。手工构造时最易漏这一点——`StreamManager` 参数为 `null` 会静默回退到默认值。

## 上手必查清单

1. 宿主是否 x64、厂商原生运行时是否已安装并在 PATH（[[项目概述/运行与安装前置条件]]）。
2. 是否调用了 `sdk.Initialize()`。
3. `cameraKey` 在 `OpenCamera` 与 `SubscribeFrameStream` 中是否完全一致。
4. 帧处理是否 `using`/`Dispose`，异步保帧是否 `AddRef` 与 `Dispose` 配对。
5. 是否传了 `whenException`（否则 handler 一次异常就静默摘除订阅）。
6. 丢帧时看 `GetStreamStatistics(cameraKey).Dropped`，而不是猜。
7. 接收方容器里 `ICameraService` 是否注册为单例实例。
