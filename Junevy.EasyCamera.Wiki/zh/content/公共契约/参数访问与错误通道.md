## 推荐入口

写参数用 `SetParam`（4 个重载：`string` / `int` / `bool` / `float`）、`SetEnumParam`、`ExecuteCommand`、`SetTrigger`——它们全部返回 `CameraResult`。

读参数**优先**用 `TryGetParam<T>` / `TryGetEnumParam`：

```csharp
if (service.TryGetParam<float>("cam1", "ExposureTime", out var exposure))
    Apply(exposure);
// false 表示：相机不可用 / 参数名无效 / 类型不支持 / 读取失败
```

`GetParam<T>` / `GetEnumParam` 是薄封装，实现就是 `TryXxx ? value : default`——失败时分别返回 `default(T)` 与**空字符串**（不是 `null`）。

> [!warning] `GetParam<T>` 语义上无法区分"参数值恰好等于默认值"和"读取失败"。曝光时间正好为 `0`、增益正好为 `1` 这类合法值会与失败混淆。业务逻辑里凡是要区分这两种情况的，一律用 `Try` 版本。

## ParameterReader 分发

厂商只实现 `IParameterSource` 的 6 个原语，泛型分发统一在 `Junevy.EasyCamera.Core/Common/ParameterReader.cs` 的静态类 `ParameterReader` 中：

```csharp
public static bool TryRead<T>(IParameterSource source, string paramName, out T value)
```

行为约定：

- 支持 `int`、`long`、`float`、`double`、`bool`、`string` 六种 `T`；**其它类型一律返回 `false`**（不抛异常）。
- `source == null` 或 `paramName` 为 `null`/空字符串 → `false`（用的是 `string.IsNullOrEmpty`，纯空白字符串**不会**在这里被拦截，交给厂商原语判定）。
- 任一原语返回 `false` → `false`，`value` 保持 `default`。
- `string` 原语返回 `null` 时**兜底为空串**（`stringValue ?? string.Empty`），不把 `null` 交给上层。
- 整个分发体包在 `try/catch` 里：**厂商异常一律按读取失败处理**，`value = default` 并返回 `false`。注释写明理由："读取失败不能表现为'值为 default'，异常一并当失败处理"。

配套的窄化转换工具：

```csharp
public static bool TryConvertToInt64ToInt32(long value, out int result)
```

越界（`< int.MinValue` 或 `> int.MaxValue`）时 `result = 0` 并返回 `false`。

## 窄化转换纪律

> [!danger] `long` → `int` 强转会**静默回绕**（溢出后按低位截断），历史上因此把"超范围的曝光值"变成一个看起来合法的正整数继续下发。现在一律走 `TryConvertToInt64ToInt32`，越界算"取值失败"，禁止回绕。

新增长整型参数的读取时：先 `TryReadLong`，再 `TryConvertToInt64ToInt32`，两步都成功才算取值成功；不要写 `(int)longValue`。

## 厂商侧取参实现

海康 `HikCamera` 显式实现 `IParameterSource` 的 6 个原语。原语**本身不取 `operationGate`**，由调用它们的 `TryGetParam<T>`（内部 `TryExecuteGuarded` 包住 `ParameterReader.TryRead(this, ...)`）统一保护——也就是说只能经 `TryGetParam<T>` 访问，直接把相机强转成 `IParameterSource` 去调原语会绕过守卫。要点：

- 取参得到的 `MvError` 不是 `MV_OK` 即返回 `false`。
- `string` 原语：`value = stringValue.CurValue ?? string.Empty`。
- `double` 原语：SDK 没有独立的 double 参数节点，由 `TryReadFloat` 结果**提升**为 `double`。因此海康的 `double` 只有 float 精度，业务上不要依赖第 17 位有效数字——那不是 SDK 侧的数据。

## LastError 通道

`ICamera.LastError` 是**厂商诊断的唯一出口**（1.1.0 起提升到接口），用于承载"返回值表达不了"的信息。门面负责透传：

| 门面方法 | 失败时对 `LastError` 的处理 |
| --- | --- |
| `StopGrab` | native 失败时，海康底层返回 `CameraResult.Fail(原生码, "Stop grabbing failed")` 并 `SetLastError("Stop grabbing failed with error code …")`；门面对 `!result.IsSuccess` **直接原样返回该结果**（`Message` 是泛化文案，详细错误码文案只在 `LastError`）。只有在"返回成功但 `camera.IsGrabbing` 仍为真"这条防御分支里，门面才返回 `Fail(-1, camera.LastError ?? "Camera stop grabbing failed")`（海康实现下基本不可达） |
| `SetTrigger` | 同上：停流失败原样返回；停流"成功"后仍 `IsGrabbing` 才透传 `LastError`。`StartGrab` 失败同样只返回底层 `CameraResult`，不附 `LastError` |
| `Close` | 映射 `CameraRemoveStatus.ReleaseFailed` 为 `Fail(-1, "The camera has been removed from the registry and released, but the release reported errors: {LastError}")`（1.1.2 起） |

另一条同构通道是 `ICameraManager.LastError`：释放相机时收集 `Close`/`Dispose` 的错误信息（多个错误用 `"; "` 连接），**成功清理后清空为 `null`**，避免陈旧错误误导后续诊断。

> [!tip] 排查顺序：先看 `CameraResult.IsSuccess`，成功就跳过；失败再读 `Code`（厂商原生码）与 `Message`，**需要完整诊断时再读 `ICamera.LastError`**（门面只在少数分支把它塞进 `Message`，`AGENTS.md` 里"门面必须透传 `LastError` 到 `Message`"是约定目标，目前并未全覆盖）。释放失败时读 `ICameraManager.LastError`。

## 错误通道选择表

| 场景 | 应使用 | 不要使用 |
| --- | --- | --- |
| 写参数 / 执行命令 | `SetParam` / `SetEnumParam` / `ExecuteCommand` 的 `CameraResult` | `void` 返回 + 事后查状态 |
| 读参数（需要区分失败） | `TryGetParam<T>` / `TryGetEnumParam` | `GetParam<T>` |
| 读参数（值可忽略） | `GetParam<T>` / `GetEnumParam` | 捕获异常判失败 |
| 生命周期（开/关/停流） | `CameraResult` + `ICamera.LastError` | 让 `MvException` 穿透 |
| 订阅成败 | `SubscribeFrameStream` 的 `bool` | 假设订阅永远成功 |
| 释放相机失败诊断 | `CameraRemoveStatus` + `ICameraManager.LastError` | 只看 `Close` 是否抛异常 |

## 历史缺陷

> [!danger] 早期 `GetParam<T>` 用 `default(T)` 吞掉一切失败——既无法区分"值恰为 default"与"失败"，又**绕开了库内已经成熟的 `CameraResult` 错误通道**，导致参数错误在调用链上彻底不可见。1.1.0 的修正方向是两条并行：`Try` 版本补上可区分性，所有新增错误路径一律走 `CameraResult`，厂商异常由守卫翻译。

同一时期还有一处相关缺陷：参数与命令路径（`SetParam`×4、`SetEnumParam`、`ExecuteCommand`、`TryGetParam`、`TryGetEnumParam`）曾完全在互斥之外，与 `Dispose` 并发时会抛 `NullReferenceException` 穿透到调用方。现在这些路径全部经 `TryExecuteGuarded` / `ExecuteGuarded`，见 [[并发与资源/并发纪律]]。
