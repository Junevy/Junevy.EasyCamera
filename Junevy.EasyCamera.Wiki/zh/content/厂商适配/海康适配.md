## 类型清单

`Junevy.EasyCamera/Vendors/HikVision/` 下四个公开类型 + 一个 SDK 系统：

| 类型 | 实现的接口 | 职责 |
| --- | --- | --- |
| `HikCamera` | `ICamera` + `IParameterSource` + `IBufferConfigurable` | 生命周期、取流、参数访问、采集缓冲配置 |
| `HikFrameWrapper` | `IFrame` | 单帧图像与引用计数，持有 SDK 克隆帧 |
| `HikCameraProvider` | `IVendorCameraProvider` + `ILinkStatusProbeProvider` | 枚举、创建、接口类型映射、可达性探测 |
| `HikCameraInfo` | `ICameraInfo` + `INamedCameraInfo` | 设备元数据，本地改名，持有 `internal IDeviceInfo Native` |
| `HikCameraSdkSystem` | `ICameraSdkSystem` | 进程级 `SDKSystem.Initialize/Finalize` 引用计数 |

关键私有字段：`IDevice device`、`IStreamGrabber streamGrabber`、`int bufferCount`、`string lastError`、`int inFlightCallbacks`。其中 `streamGrabber`、`lastError`、`inFlightCallbacks` 受 `object stateLock` 保护；`device` 与 `bufferCount` 主要在 `operationGate` 内读写（公开属性 `IsConnected` 会在门外读 `device`，靠先判 `state` 再判 `device != null` 兜底；未打开时的 `SetBufferCount` 也在门外写 `bufferCount`）。

## 并发骨架：门与三守卫

`SemaphoreSlim operationGate = new(1, 1)` 串行化**全部**原生访问，三个守卫收敛互斥、异常翻译与诊断：

| 守卫 | 形态 | 用途 |
| --- | --- | --- |
| `ExecuteGuarded(Func<CameraResult>)` | 返回 `CameraResult` | `Connect` / `Close` / `StartGrab` / `StopGrab` 及全部 `SetParam`、`SetEnumParam`、`ExecuteCommand`、`IBufferConfigurable.SetBufferCount`（已打开时） |
| `TryExecuteGuarded<T>(Func<(bool Ok, T Value)>, out T)` | 返回 `bool` | `TryGetParam<T>` / `TryGetEnumParam`，以"是否取到值"表达结果 |
| `ExecuteDispose(Action)` | 无返回值、不外泄异常 | `Dispose` |

三者都 `operationGate.Wait()` / `finally Release()` 并写 `LastError`，但异常翻译各不相同：只有 `ExecuteGuarded` 单独捕获 `MvException` 取 `ErrorCode` 作为 `CameraResult.Code`、其他异常统一 `Fail(-1, message)`；`TryExecuteGuarded` 把一切异常收敛为 `false`；`ExecuteDispose` 吞掉异常。相机契约要求"失败一律通过返回值表达"，绝不让异常穿透到调用方。

> [!warning]
> 1.1.0 之前 `SetParam`×4 / `SetEnumParam` / `ExecuteCommand` / `TryGetParam` / `TryGetEnumParam` 既不加锁也不经 `operationGate`，与 `Dispose` 并发时会抛 `NullReferenceException` 直接穿透。新增写操作**必须**并入 `ExecuteGuarded`，否则会重现 use-after-free。

## 生命周期状态机

私有 `enum CameraState { Closed = 0, Open = 1, Grabbing = 2, Closing = 3, Disposed = 4 }`，以 `int state` 承载、`Volatile` 读写。它取代了历史上的五个布尔标志位（`isOpen` / `isGrabbing` / `closing` / `callbacksEnabled` / `disposed`），从结构上排除非法组合。

- `IsConnected`：状态为 `Open` / `Grabbing` / `Closing` **且** `device != null` **且** `device.IsConnected`（`Closing` 计入，因为此时设备尚未释放）。
- `IsGrabbing`：状态恰为 `Grabbing`。
- 发布判定：回调里只比较一次状态，`Open` 或 `Grabbing` 才发布。

## 打开与关闭主线

`ConnectCore`：检查已释放 / 已连接 → `device ??= deviceFactory(deviceInfo)` → `device.Open()`（返回 `MvError`，`MV_OK` 为成功）→ 取 `device.StreamGrabber`（为 null 视为失败并 `SafeClose`）→ 置 `Open` → **先 `-=` 再 `+=` 绑定 `FrameGrabedEvent`** → 可选地应用 `bufferCount`（失败不影响可用性）。绑定阶段的异常会回滚到 `Closed`、清空 `streamGrabber`、解绑、`SafeClose`。

`CloseCore`：置 `Closing`（回调线程立刻停止发布帧）→ 解绑回调 → `StopGrabCore` → `WaitForCallbacks()` → `device.Close()`。

> [!danger]
> 关闭路径上**任何**失败都必须经 `RestoreAfterFailedClose` 回滚到 `previousState` 并重新绑定回调订阅。1.1.0 之前的 `catch` 分支不回滚，相机永久停在"关闭中"——`IsConnected` 仍为 true 却一帧都不再下发，静默丢帧且无任何报错。

`StopGrabCore` 只在 native 成功后才回落状态，且回落条件是"当前状态恰为 `Grabbing`"；关闭路径上状态已是 `Closing`，因此不会被改回 `Open` 而让回调复活。`StopGrab` 未在取流时直接返回成功（幂等）。

## 采集回调与帧包装

`ProcessFrameCallBack` 运行在 SDK 采集线程，纪律是"不外泄异常、必归还缓冲"：

1. `lock (stateLock)` 内 `inFlightCallbacks++`，同时读状态得出 `shouldPublish`，并捕获 `fallbackGrabber = streamGrabber`。
2. `shouldPublish` 时 `frameOut.Clone()`（**每帧仅此一次**）→ `new HikFrameWrapper(cloned)` → `stream.Publish(frame)`，随即把局部 `frame` 置 `null`（所有权移交数据流）。克隆非空但不是 `IFrameOut` 时立即 `Dispose` 该克隆，避免泄漏。
3. `finally` 中 `(callbackGrabber ?? fallbackGrabber)?.FreeImageBuffer(frameOut)`——用回调来源取流器或进入回调时捕获的取流器，不依赖 Dispose 后会被清空的 `device` 字段。
4. 内层 `finally` 递减 `inFlightCallbacks`，归零时 `Monitor.PulseAll`。

`HikFrameWrapper`：

- 构造时**一次性快照** `width` / `height` / `imageSize` / `pixelType` / `stride`（`stride = imageSize / height` 推算，SDK 没有独立步长字段）。此后这些属性全是字段读取，既省掉每帧穿透 SDK，也消除"先判已释放再读原生内存"的 check-then-use 竞态。
- `refLock` 串行化 `AddRef` / `Dispose` 与 `Data` / `PixelDataPtr` / `GetBitmap` 的原生访问；与"引用归零的物理释放"互斥。
- 引用计数初始为发布方的 1；`AddRef` 在已释放帧上抛 `ObjectDisposedException`；`Dispose` 幂等（重复释放不把计数压到负数），归零后由**最后一个释放者**执行 `native.Dispose()`——不得固定为发布者，否则其余浅引用悬空。
- `Data` 懒缓存托管副本（SDK 的 `PixelData` 每次访问可能重新拷贝 5MB+）；已释放且已缓存则返回缓存副本，从未访问过则返回 `Array.Empty<byte>()`；`PixelDataPtr` 已释放返回 `IntPtr.Zero`；`GetBitmap` 已释放返回 `null`。
- 终结器 `~HikFrameWrapper` 兜底释放克隆帧；正常 `Dispose` 成功后 `GC.SuppressFinalize`。
- `ConvertFormat` 把 `MvGvspPixelType` 映射到 `ImagePixelFormat`，未覆盖的落到 `Unknown`。

`WaitForCallbacks` 用 `Monitor.Wait(stateLock, remaining)` 等待，上限 `CallbackDrainTimeout = TimeSpan.FromSeconds(5)`；超时写 `LastError` 并继续关闭，绝不永久阻塞 `Close` / `Dispose`。

## 参数访问

| 面 | 路径 |
| --- | --- |
| 写 | `SetParam`（int/float/bool/string）、`SetEnumParam`（按符号名）、`ExecuteCommand`，全部经 `ExecuteGuarded` |
| 读 | `TryGetParam<T>` / `TryGetEnumParam` 经 `TryExecuteGuarded`；泛型分发统一交给 `ParameterReader.TryRead<T>` |
| 原语 | `IParameterSource` **显式实现** 6 个 `TryReadXxx` |

细节：

- `CurrentParameters()` 返回 `null`（相机未连接或已释放）时，调用方一律返回 `ParametersUnavailable()`（`Fail(-1, "The camera parameters are not available.")`）——**不得报成功假象**。
- 海康参数节点没有独立 `double` 类型，`TryReadDouble` 由 `TryReadFloat` 提升而来。
- `TryConvertToInt64ToInt32` 是 `internal static`，委托 `ParameterReader`；`long`→`int` 越界按"取值失败"处理，禁止静默回绕。
- `IBufferConfigurable.SetBufferCount(int)` 也是显式实现：`count < 1` 直接失败；未打开时只记录配置（延迟到 `Connect` 成功后由 `TryApplyBufferCount` 应用）；已打开时经 `ExecuteGuarded` 调 `grabber.SetImageNodeNum`。

## 枚举与链路状态探测

`ToLayerType` 私有静态映射：

| `CameraInterfaceType` | `DeviceTLayerType` |
| --- | --- |
| `GigE` | `MvGigEDevice` |
| `Usb` | `MvUsbDevice` |
| `CameraLink` | `MvCameraLinkDevice` |
| `GenTL` | `MvGenTLGigEDevice \| MvGenTLCameraLinkDevice \| MvGenTLCXPDevice \| MvGenTLXoFDevice` |
| `All` | 上述 + `MvVirGigEDevice` + `MvVirUsbDevice`（共 9 个传输层） |
| `Unknown` 及默认 | `(DeviceTLayerType)0` |

枚举失败（返回码非 `MV_OK` 或列表为 null）时输出 `Trace.TraceWarning` 并 `yield break`——目前只能用空集合表达，但绝不静默。

`HikCameraProvider.ProbeLinkStatus`（实现 `ILinkStatusProbeProvider`）：

1. `info` 为 null 或序列号为空 → `Unknown`。
2. 按 `info.InterfaceType` 缩小枚举范围，仅 `Unknown` 时才全量 `All`。
3. 重新枚举、按序列号（`StringComparison.Ordinal`）匹配取**新鲜** `HikCameraInfo`；找不到 → `Unreachable`。
4. 找到则 `DeviceEnumerator.IsDeviceAccessible(fresh.Native, DeviceAccessMode.AccessExclusive)`：`true` → `Idle`，`false` → `Occupied`。

> [!tip]
> 探测刻意**不信任调用方传入的原生引用**（可能已过期），必须重新枚举。查询取独占模式，与 `HikCamera` 调 `device.Open()` 无参重载的默认权限一致，所以"可达"≈"可连接"——这也意味着本进程已独占持有的相机会被报成 `Occupied`，因此 `CameraService` 的自持早退必须先行。

`HikCameraInfo.GetCameraType` 反向映射：`MvGigEDevice` 与 `MvVirGigEDevice` 都是 `GigE`，`MvUsbDevice` 与 `MvVirUsbDevice` 都是 `Usb`，四个 GenTL 子类型都是 `GenTL`，其余 `Unknown`。`INamedCameraInfo.SetDefinedName` 只改本地副本，长度 ≤64，仅本地改名不下发设备。

## SDK 初始化与引用计数

`HikCameraSdkSystem` 的 `SDKSystem.Initialize/Finalize` 是进程级全局操作，因此用**静态** `initRefCount` + 静态 `refCountLock` 串行化计数转移：

- 每实例 `initialized` / `disposed` 标记实现"按实例幂等"——重复 `Initialize` 只持一个全局引用。
- 未 `Initialize` 的实例调 `Release` 直接返回，不削减他人引用。
- `Interlocked.Increment` 返回 1 时才真正 `SdkInitializeAction()`；初始化抛异常则回退计数并继续抛出（不留悬挂引用）。
- `Interlocked.Decrement` 归 0 时才真正 `SdkFinalizeAction()`。
- 锁序为 `instanceLock` → `refCountLock`，多实例间无反向持锁路径。

测试 seam：`internal static Func<int> SdkInitializeAction` / `SdkFinalizeAction` 默认指向 `SDKSystem.Initialize` / `Finalize`，经 `InternalsVisibleTo("Junevy.EasyCamera.Tests")` 供无硬件测试替换。

`HikCamera` 也有一个构造 seam：`HikCamera(IDeviceInfo info, ICameraStream stream, Func<IDeviceInfo, IDevice> deviceFactory)`，生产路径用 `DeviceFactory.CreateDevice`。这让生命周期测试可以用假 `IDevice` / `IStreamGrabber` / `IFrameOut` 跑通全部状态机路径。
