## 本分类概述

本分类覆盖从"仓库源码"到"消费方能用"的整条链路：三个 SDK 风格工程（`Junevy.EasyCamera.Core` / `Junevy.EasyCamera` / `Junevy.EasyCamera.Tests`）双目标 `net48` + `net8.0`，厂商 SDK DLL 统一从仓库根 `Libs/` 引用，中央包管理 + `global.json` 固定 SDK 版本保证可复现。1.1.1 的核心主题是一个 P0 缺陷：**厂商托管封装从未打进 NuGet 包**——`<Reference HintPath>` 只让本仓库输出目录拿到 DLL，`dotnet pack` 既不打包文件引用也不产生依赖声明，结果是"本仓库 build/test 全绿、消费方还原后必崩"。这类缺陷单元测试天然测不到，因此必须直接校验打包产物，这也催生了 `PackageContentTests` 这个守卫。三条硬约束常被违反：`PackagePath` 必须逐 TFM 写全、打包用的 `ItemGroup` 不能按 `$(TargetFramework)` 分条件、修复打包类问题时**必须递增版本**（NuGet 按 `id + version` 缓存）。

## 构建与验收基线

```powershell
dotnet build .\Junevy.EasyCamera.sln -c Release -v:minimal --no-incremental
dotnet test .\Junevy.EasyCamera.Tests\Junevy.EasyCamera.Tests.csproj -c Release --logger "console;verbosity=minimal"
```

必须 `--no-incremental`：`GenerateAssemblyInfo=false` 的连带影响曾让 `CA1416` 告警在**增量构建里看不见**、全量重建才暴露 20+ 条。

其他环境约定：

| 项 | 值 |
| --- | --- |
| SDK 版本 | `global.json` 固定 `9.0.316`（`rollForward: latestFeature`） |
| 第三方包版本 | 由 `Directory.Packages.props` 中央包管理统一维护 |
| 本库版本 | `1.1.1`，写在 `Junevy.EasyCamera.csproj` 与 `Junevy.EasyCamera.Core.csproj` 各自的 `<Version>`，并与两个类库各自 `Properties/AssemblyInfo.cs` 的 `AssemblyVersion`/`FileVersion`（`1.1.1.0`）**四处同步**；`SKILL.md` frontmatter 里的版本提示同步更新。主包 nuspec 声明对 Core 的**同版本**依赖 |
| 目标框架 | `net48;net8.0`（消费方另有 net48 兼容包） |
| 运行时位数 | `PlatformTarget=x64`（`Junevy.EasyCamera` 与 `Junevy.EasyCamera.Tests` 固定；**`Junevy.EasyCamera.Core` 未设置**——它是纯契约层，不触碰厂商 SDK） |
| 平台标注 | `Properties/PlatformCompatibility.cs` 中 `#if NET8_0_OR_GREATER` 声明 `SupportedOSPlatform("windows")` |
| 打包触发 | 两个类库都设了 `GeneratePackageOnBuild=true`；产物在 `Junevy.EasyCamera/bin/<Config>/` 与 `Junevy.EasyCamera.Core/bin/<Config>/`（按 Debug/Release，不按 TFM 分目录；旧版本的 nupkg 会一直留在里面） |

验收基线（2026-10-09，1.2.0 验收修正后）：全量重建 0 错误 0 警告；`net48` 与 `net8.0` 各 **149/149** 通过（1.1.1 发布时为 124，1.1.2 批次 A 新增 9 项，1.2.0 掉线批次新增 16 项），且仓库内 `[TestMethod]` 总数 == 执行数。
