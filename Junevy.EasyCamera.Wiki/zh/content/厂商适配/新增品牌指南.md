## 第 0 步：确认是否需要新增能力接口

**默认不需要。** `ICameraProvider` 只要求所有厂商都必须支持的三个动作：`Supports` / `Create` / `Enumerate`（两个重载）。`IVendorCameraProvider` 只多一个 `VendorName`。

只有当某项能力**海康有、其他品牌没有**，且外部实现者也未必能做时，才新增独立能力接口（如 `ILinkStatusProbeProvider` / `IBufferConfigurable` / `INamedCameraInfo`）。加在 `ICameraProvider` 上是破坏性的：每加一个成员，所有外部实现者（含第三方品牌）都被迫修改。

判断方法与纪律见 [[厂商适配/厂商能力实现指南]]。

## 第 1 步：建 `Vendors/<Brand>/` 目录与五个类型

| 类型 | 接口 | 关键点 |
| --- | --- | --- |
| `<Brand>Camera` | `ICamera` + `IParameterSource` | 生命周期、取流、参数 |
| `<Brand>FrameWrapper` | `IFrame` | 帧数据与引用计数 |
| `<Brand>CameraProvider` | `IVendorCameraProvider` | 枚举、创建、接口类型映射 |
| `<Brand>CameraInfo` | `ICameraInfo` | 设备元数据，持有 `internal` 原生句柄 |
| `<Brand>CameraSdkSystem` | `ICameraSdkSystem` | 进程级 Initialize/Release |

参照 `Junevy.EasyCamera/Vendors/HikVision/` 的五个文件。华睿（IRayple）是反例参考：`IRaypleCameraProvider` 早期带一个 `ProbeLinkStatus` 空桩，成员迁到能力接口后已移除——**不要在 provider 上留能力接口的空实现桩**。

## 第 2 步：相机类必须照海康执行并发纪律

逐条对照 `HikCamera`：

1. `SemaphoreSlim operationGate = new(1, 1)` 串行化**全部**原生访问，收敛为三个守卫：`ExecuteGuarded(Func<CameraResult>)`、`TryExecuteGuarded<T>(Func<(bool Ok, T Value)>, out T)`、`ExecuteDispose(Action)`。三者都做"互斥 + 异常翻译成 `CameraResult` + `LastError`"。
2. **单一状态枚举**（海康 `CameraState`：`Closed` / `Open` / `Grabbing` / `Closing` / `Disposed`），`int` 承载 + `Volatile` 读写。不得引入并行布尔标志位；发布判定只看状态。
3. **失败路径必须回滚**。海康的 `RestoreAfterFailedClose` 是模板：任何关闭失败都恢复进入前状态并重新绑定回调订阅。
4. **回调线程只做三件事**：递增在途计数、读状态判定、归还帧/缓冲。异常绝不外泄（会中断 SDK 采集）。
5. **释放前排空在途回调**：`Monitor.Wait` + `CallbackDrainTimeout = TimeSpan.FromSeconds(5)`，超时写 `LastError` 并继续关闭。
6. **`LastError`** 是厂商诊断的唯一出口，成功完成后清空。

> [!danger]
> 海康曾长期用 `isOpen` / `isGrabbing` / `closing` / `callbacksEnabled` / `disposed` 五个布尔标志位，其中 `catch` 分支忘记回滚 `closing`，导致相机永久停在"关闭中"：`IsConnected` 为 true 却一帧都不再下发，且无任何报错。新品牌直接用状态枚举，不要重复这个坑。

## 第 3 步：帧包装器

1. **深拷贝策略**：海康在采集回调内 `frameOut.Clone()` **每帧仅一次**，多订阅者通过引用计数浅共享同一个克隆（订阅者是只读消费者）。逐订阅者深拷贝会打爆相机缓存队列、丢帧。
2. **引用计数**：初始为发布方的 1；`AddRef` 在已释放帧上抛 `ObjectDisposedException`；`Dispose` 幂等（重复释放不把计数压到负数）。
3. **物理释放者是最后一个归零的持有者**，不得固定为发布者，否则其余浅引用悬空。
4. **构造期快照元数据**（宽/高/大小/步长/像素格式），之后全部字段读取，消除 check-then-use 竞态。
5. **终结器兜底**：持有非托管缓冲的包装器必须有 `~<Brand>FrameWrapper`；正常 `Dispose` 成功后 `GC.SuppressFinalize`。
6. 仍需触碰原生内存的入口（`Data` / `PixelDataPtr` / `GetBitmap`）必须在同一把锁内执行，与物理释放互斥；已释放时分别返回空数组 / `IntPtr.Zero` / `null`。

华睿采用另一种合法策略：`IRaypleFrameWrapper` 构造时即 `Marshal.Copy` 成托管数组，原生帧在回调内归还，因此它没有非托管缓冲，也就不需要终结器。

## 第 4 步：取参

实现 `IParameterSource` 的 **6 个原语**：`TryReadInt` / `TryReadLong` / `TryReadFloat` / `TryReadDouble` / `TryReadBool` / `TryReadString`。

- **不要自己写 `typeof` 链**。泛型分发与失败语义统一由 `ParameterReader.TryRead<T>` 处理，厂商只提供原语。
- **`long`→`int` 必须受检转换**：调 `ParameterReader.TryConvertToInt64ToInt32`，越界按"取值失败"返回 false，禁止静默回绕。
- 厂商没有某精度时按"提升"处理（海康无独立 `double` 节点，由 `float` 提升）。
- 取参失败一律 `false`，以便 `TryGetParam<T>` 区分"值恰为 default"与"取值失败"。

## 第 5 步：能力接口按需实现

`IBufferConfigurable` / `INamedCameraInfo` / `IParameterSource` 用**显式实现**，避免扩大具体类的公开面（海康的 `HikCamera.SetBufferCount`、`HikCameraInfo.SetDefinedName`、六个 `TryReadXxx` 都是显式实现）。`ILinkStatusProbeProvider` 是 provider 级能力，海康里是**公共（隐式）实现**（`HikCameraProvider.ProbeLinkStatus` 为 `public`），`AggregateCameraProvider` 同样；新品牌可照此，也可改显式，但不要因此误以为"海康全部显式"。逐个接口的写法见 [[厂商适配/厂商能力实现指南]]。

## 第 6 步：引用厂商 DLL 与打包

1. 把厂商 SDK DLL 放进仓库根 `Libs/`（保持单一来源，不复制到工程目录）。
2. 在 `Junevy.EasyCamera/Junevy.EasyCamera.csproj` 加 `<Reference>` + `HintPath` + `<Private>true</Private>`。
3. **同时**新增无条件 `Pack` 项：

```xml
<ItemGroup>
    <None Include="..\Libs\<Brand>.Net.dll" Pack="true" PackagePath="lib/net48;lib/net8.0" Visible="false" />
</ItemGroup>
```

> [!warning]
> 第 3 步漏掉就是 1.1.0 的 P0 缺陷：`<Reference HintPath>` 只让本仓库输出目录拿到 DLL，`dotnet pack` 既不打包文件引用也不产生依赖声明，消费方还原后必崩而本仓库全绿。两个坑（`PackagePath="lib/"` 会被 NuGet 整体忽略、不能按 `$(TargetFramework)` 分条件）详见 [[构建与发布/NuGet打包规则]]。

4. 在 `Junevy.EasyCamera.Tests/Packaging/PackageContentTests.cs` 的 `RequiredVendorAssemblies` 加上该厂商的两个 TFM 路径。

## 第 7 步：注册与开关

四处联动，缺一不可：

| 位置 | 改动 |
| --- | --- |
| `Extensions/CameraOptions.cs` | 新增 `Enable<Brand> { get; set; }` |
| `Extensions/ServiceCollectionExtensions.cs` | `AddEasyCamera` 中按开关调用 `Register<Brand>()`；新增厂商开关方法；`sdkSystemFactories.Add(...)` |
| `Common/EasyCameraBuilder.cs` | 新增 `Enable<Brand>()`，往 `providerFactories` / `sdkFactories` 各加一项 |
| `Extensions/ServiceCollectionExtensions.cs` 的 `Register<Brand>()` | `TryAddSingleton<<Brand>CameraSdkSystem>()` + `TryAddEnumerable(ServiceDescriptor.Singleton<IVendorCameraProvider, <Brand>CameraProvider>())` |

要点：

- provider **必须**用"服务类型 + 实现类型"方式注册（`TryAddEnumerable(ServiceDescriptor.Singleton<IVendorCameraProvider, XxxCameraProvider>())`）。工厂委托注册会让 `TryAddEnumerable` 按委托签名而非实现类型判重，多厂商场景下只注册成功第一个。
- 未完成的品牌与 DI 路径保持一致：`RegisterIRayple()` 与 `EasyCameraBuilder.EnableIRayple()` 都抛 `NotImplementedException`，与厂商类型的 `[Obsolete(..., true)]` 标记一致。
- 组合 SDK 系统 `CompositeCameraSdkSystem` 按工厂延迟构建，避免与 `IEnumerable<ICameraSdkSystem>` 形成自引用解析。

## 第 8 步：测试

- 用桩件（fake device / grabber / frameOut）覆盖生命周期，不要依赖真实硬件。海康的做法是给相机加构造 seam：`HikCamera(IDeviceInfo, ICameraStream, Func<IDeviceInfo, IDevice>)`，SDK 系统加 `internal static Func<int>` seam。
- 至少覆盖：状态迁移全链、关闭失败回滚、回调异常仍归还缓冲、释放后操作快速失败、释放后回调不发布、取参在释放后返回失败而不抛异常、传输层映射不把 `Unknown` 扩大为 `All`。
- **新增测试文件必须手工加入 `Junevy.EasyCamera.Tests.csproj` 的 `<Compile>` 清单**。该项目 `EnableDefaultCompileItems=false`，漏登记的测试"绿色地缺席"——2026-10-06 曾因此让 6 个探测测试一次都没跑过（仓库实有 98 个 `[TestMethod]`，只执行了 92 个）。

## 第 10 步：验收

```powershell
dotnet build .\Junevy.EasyCamera.sln -c Release -v:minimal --no-incremental
dotnet test .\Junevy.EasyCamera.Tests\Junevy.EasyCamera.Tests.csproj -c Release --logger "console;verbosity=minimal"
```

1. 全量重建 **0 错误 0 警告**（必须 `--no-incremental`，增量构建看不到 `CA1416` 一类被跳过的告警）。
2. `dotnet test` 双目标（net48 + net8.0）全通过。
3. **仓库内 `[TestMethod]` 总数 == 执行数**：

```powershell
(Get-ChildItem .\Junevy.EasyCamera.Tests -Recurse -Filter *.cs | Where-Object { $_.FullName -notmatch '\\(bin|obj)\\' } | Select-String -Pattern '\[TestMethod\]' | Measure-Object).Count
```

基线（1.1.1 + 链路探测回退修复）：net48 与 net8.0 各 **130/130**，仓库内 `[TestMethod]` 总数 130。

4. 打包规则改动后，确认 `PackageContentTests` 仍通过（移除规则时它必须失败），见 [[构建与发布/包内容守卫]]。
